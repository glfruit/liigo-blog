我的上一个博客停在 2022 年。十年间断断续续写了十九篇，从 Clojure 写到 Grails 写到 Razor Pages，最后停在腾讯云上的一篇 Hexo 搭建备忘录。不是不想写，是每次想写的时候，总要先和那套老 toolchain 搏斗一番，兴致消磨殆尽，作罢。

今年 AI 工具把我的工作效率整个翻了一遍，重新有了"写下来"的欲望。这次我不想再凑合，认真做了一回选址与选型。这篇记录决策过程，后面的几篇记录怎么把这些决定落地。

## 域名：liigo.dev

先说名字。liigo 是真名"李果"的拼音缩写变体：Li + Go，两个 i 让这个词在视觉上有了自己的形状，外人看来是个独立品牌词，自己人知道里面的暗线。Go 同时双关"行动力"和 Go 语言——对一个博客来说，"去写、去做"这个寓意再好不过。

后缀选 .dev 而不是 .com，理由很实际：.com 对应的品相好的词早没了，.dev 简短、和写代码的身份相符、便宜（Cloudflare Registrar 成本价续费，一年十二美元上下）。DNS 托管也在 Cloudflare，后面接 Workers 部署零配置打通。

## 技术栈：Next.js + OpenNext + Workers

老博客是 Hexo，静态生成，本身没什么错。这次重建我想要的不是换个静态生成器，而是几样 Hexo 给不了的东西：

- **文章页全量 SSG，列表页也预渲染**。二十二篇文章的小站，没有任何理由在运行时渲染——全部在构建时生成 HTML，服务器只负责发文件。这个决定后来帮我绕开了 OpenNext 的一堆运行时坑，那是下一篇的故事。
- **MDX 本地文件 + Git**。不引入 CMS。文章就是仓库里的文件，历史、 diff、回滚全部白送。
- **部署到 Cloudflare Workers**。免费额度每天十万请求，个人博客用不完；边缘节点分发，海外读者直接受益。Vercel 当然更省事，但我不想把站点绑在一家平台的免费政策上。

具体组合是：Next.js 15（App Router）+ TypeScript + Tailwind CSS 4 + MDX，通过 @opennextjs/cloudflare 适配到 Workers。CI 是 GitHub Actions，push main 自动构建部署。

## 设计体系：单色墨纸

视觉上的决定比技术上更果断：**单色**。ink `#0a0a0a`、paper `#fafafa`、line `#e5e5e5`，全站没有第四种颜色，链接和按钮也不许变色。

理由不是极简主义洁癖，而是聚焦。彩色是最容易滥用的东西——一旦允许彩色出现，每篇文章的配图、每个按钮、每个标签都会争着抢注意力。禁掉彩色之后，版面只剩下一种秩序：排印。目录式的文章列表、发丝线分隔、衬线标题配等宽字体的元信息，像一份印在纸上的独立刊物。

logo 也按这个思路来：墨色圆角方块里两个反白的 i，圆点左高右低错落——就是 liigo 那两个 i，一枚徽章，不解释。

## 内容管线优先

这次重建最重要的一个决定，和框架无关：**`content/` 目录本身就是 Obsidian Vault 的子文件夹**。

也就是说，写作即编辑源码，发布即 git push。没有导出、没有后台、没有"待发布队列"。我在 Obsidian 里新建一篇笔记（模板自动填好 frontmatter，默认 `draft: true`），写完把 draft 改成 false，Obsidian Git 插件每十分钟自动同步一次，几分钟后文章就上线了。

内容分三个固定栏目：AI 工具（评测与使用技巧）、AI 教程（亲手验证过的深度教程）、建站笔记（本系列）。旧文统一归进 archive。分类宁少勿多，新主题先用 tag 顶着，攒够数量再升级。

## 为什么值得写这篇

选址与选型看起来是项目里最"虚"的部分，但它决定了后面所有的坑长什么样。下一篇写部署实战：把 Next.js 塞进 Cloudflare Workers 时踩的两个真坑——一个让构建报错，一个让线上站点"看起来部署成功了其实全空"。
